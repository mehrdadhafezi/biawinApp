## ۱. معرفی و هدف کلی محصول

**بیاوین (Biawin)** یک «باشگاه مشتریان / سوپراپ خرید اقساطی-اعتباری» فارسی و RTL است. شعار داخل پروتوتایپ:

> «باشگاه هوشمند تجربه‌های ارزشمند» / «راهی ساده‌تر برای خریدهای بزرگ اقساطی، دریافت اعتبار و استفاده از خدمات منتخب»

مدل کسب‌وکار بر پایه سه محور است:

1. **عضویت (Membership):** کاربر با یکی از کارت‌های عضویت (شروع، پلاس، خانواده، پرایم، هدیه، سفر، سبک زندگی، سازمانی) وارد باشگاه می‌شود.
2. **اعتبار/اقساط:** در ۱۸+ دسته خدمات (خودرو، لوازم خانگی، طلا، پوشاک، گردشگری، دیجیتال، سلامت، بیمه، ورزش و ...)، هر محصول را می‌توان به ۴ روش خرید: **اعتباری، اقساطی، پرداخت کامل، یا رایگان/جایزه**.
3. **جایزه و گیمیفیکیشن:** کیف‌پول جایزه، مأموریت‌ها (missions با پیشرفت درصدی)، امتیاز باشگاه، دعوت دوستان (referral).

یک محور چهارم متمایز: **مشاور هوش مصنوعی همراه (وین‌یار)** — سه پرسونا (وینا، وین‌یاد، آروین) با چت متنی + صدا، که در پروتوتایپ صراحتاً به‌عنوان یک UI mock علامت‌گذاری شده:

> «این نسخه نمونه رابط کاربری است و برای مشاوره هوشمند واقعی باید به سرویس هوش مصنوعی متصل شود.»

## ۲. معماری اطلاعات (نقشه صفحات)

پروتوتایپ یک **SPA تک‌فایلی با روتینگ مبتنی بر hash** است (`location.hash`، تابع `openView(name)`، سوییچ کردن کلاس `active` روی `<section class="app-view">`). ۹ ویو اصلی:

| # | data-view | نقش |
|---|---|---|
| 1 | `landing` | صفحه ورود/معرفی با ۴ باکس (کسب‌وکار، چرا بیاوین، فرصت‌های خاص، کارت‌ها) + دکمه مرکزی ورود/ثبت‌نام |
| 2 | `home` | خانه: استوری‌های معرفی، کاروسل کارت‌های عضویت، میانبرها، تیکر خدمات، بنر خدمات منتخب، کارت‌های اشتراک، اخبار |
| 3 | `card-detail` | جزئیات یک کارت عضویت (رندر داینامیک از آرایه `membershipCards`) |
| 4 | `services` | فهرست کامل دسته‌بندی خدمات (grid با دکمه «بیشتر») |
| 5 | `service-category` | زیرمجموعه محصولات یک دسته (رندر داینامیک از `categoryCatalog`) با جست‌وجو و فیلتر نوع پرداخت |
| 6 | `service-detail` | جزئیات یک محصول/خدمت: روش‌های خرید، مزایا، گالری، مراحل، FAQ، buy-bar چسبان |
| 7 | `rewards` | فروشگاه جایزه (۱۶ محصول) با کیف‌پول و مودال پرداخت ترکیبی (کیف‌پول + درگاه) |
| 8 | `advisor` | انتخاب مشاور AI (۳ پرسونا) + بیوگرافی هرکدام |
| 9 | `profile` | حساب کاربری: کیف‌پول، کارت‌های فعال، آمار، آکاردئون‌های (حساب، کارت‌ها، سفارش‌ها، مأموریت‌ها، آدرس‌ها، دعوت دوستان، اعلان‌ها، پشتیبانی) |

**Bottom Navigation** فقط ۴ آیتم دارد: خانه / خدمات / جایزه / پروفایل. صفحه مشاور از طریق یک **دکمه شناور سراسری (`advisorFloat`)** و لایه چت روی همه صفحات در دسترس است — نه از bottom nav.

**Overlay/Modal های سراسری** (خارج از app-view ها، در سطح بدنه صفحه):
- `authModal` — ورود/ثبت‌نام ۳ مرحله‌ای (شماره موبایل → کد OTP ۶ رقمی → تکمیل پروفایل)
- `firstOnboarding` — تور آموزشی ۶ اسلایدی با اسکرین‌شات و hotspot (فقط برای کاربر جدید)
- `advisorChatLayer` — پنل چت مشاور با ورودی صدا (میکروفن) و پخش صوتی پاسخ
- `introStoryViewer` / `storyViewer` — استوری‌های تمام‌صفحه با تایمر و نوار پیشرفت
- `rewardModal` — جزئیات جایزه + تقسیم پرداخت کیف‌پول/درگاه + فرم شبیه‌سازی‌شده درگاه بانکی
- `purchaseSheet` — تأیید نهایی خرید خدمت (bottom sheet)
- `logoutConfirmModal`, `appGuideModal`

## ۳. سیستم طراحی (Design System) استخراج‌شده

### هویت بصری
- فونت: **Vazirmatn** (وزن‌های ۳۰۰ تا ۸۰۰)، جهت RTL، زبان فارسی با اعداد فارسی (۰۱۲۳...).
- شکل کلی: موبایل‌فرست، container تکی با `max-width: 760px` وسط‌چین (طراحی شبیه یک اپ موبایل داخل مرورگر دسکتاپ).
- `theme-color`: `#0879dc`

### پالت رنگ (CSS Custom Properties)
| توکن | مقدار | کاربرد |
|---|---|---|
| `--primary` | `#0879dc` | رنگ اصلی برند (آبی) |
| `--primary-2` | `#0a63b8` | حالت گرادیانت/hover |
| `--deep` | `#074f98` | تیتر‌ها، تیره‌تر از primary |
| `--ink` | `#0e2f4d` | متن اصلی |
| `--muted` | `#6f8497` | متن ثانویه |
| `--ice` | `#f2f8fd` | پس‌زمینه روشن |
| `--line` | `#d9eafb` | خطوط جداکننده/border |

رنگ‌های تاکید ثانویه به‌ازای بخش: نارنجی `#f28a2d`/`#ff8b2b` (فرصت‌های ویژه)، طلایی/رزگلد در کارت‌های VIP، و هر پرسونای مشاور رنگ اختصاصی خودش (طلایی، فیروزه‌ای، بنفش) دارد. هر دسته خدمت هم یک theme رنگی مجزا (`theme-auto`, `theme-home`, `theme-fashion`, `theme-gold`, `theme-travel`, ...).

### مقیاس فاصله‌گذاری و اشکال
- `--radius: 24px` (استاندارد کارت‌ها)، دکمه‌ها و آیکون‌ها با شعاع کوچک‌تر (10–18px)
- سایه‌ها استاندارد: `--shadow: 0 18px 50px rgba(4,79,152,.13)` و `--shadow-sm` برای سطوح کم‌عمق‌تر
- هدرها sticky با `backdrop-filter: blur(16-18px)` (افکت شیشه‌ای/glassmorphism)
- کارت‌های اعتباری (credit card) با نسبت تصویر واقعی کارت بانکی (`aspect-ratio: 1.62/1`) و افکت گرادیانت + دایره نوری تزئینی

### الگوهای کامپوننتی تکرارشونده
- **Bottom Nav ثابت** (4 آیتم + دکمه شناور مشاور)
- **Header sticky + جعبه جست‌وجو** در بیشتر صفحات
- **کاروسل افقی با اسنپ** (`scroll-snap-type: x mandatory`) — برای کارت‌های عضویت، استوری‌ها، اخبار، محصولات
- **Story bubble ring** (شبیه اینستاگرام) برای استوری‌های معرفی و کارت‌های اشتراک
- **کارت خدمت/محصول استاندارد**: تصویر + عنوان + برچسب نوع پرداخت (اقساطی/اعتباری/تخفیفی/ترکیبی)
- **Accordion** برای بخش‌های پروفایل
- **Sticky buy-bar** پایین صفحه جزئیات خدمت
- **Bottom sheet مودال‌ها** با handle در بالا (الگوی موبایل نیتیو)
- **Toast** برای پیام‌های موفقیت کوتاه‌مدت

نتیجه: سیستم طراحی به‌قدر کافی سازگار و آماده‌ی استخراج به یک **Design Token file + کتابخانه کامپوننت (Design System)** واقعی است (رنگ‌ها، تایپوگرافی، فاصله‌گذاری و کامپوننت‌ها الگوی ثابتی دارند).

## ۴. الگوهای فنی فرانت‌اند در پروتوتایپ فعلی

- **بدون فریم‌ورک**: HTML/CSS/JS خام در یک فایل، بدون build step، بدون ماژول.
- **روتینگ**: دستی، مبتنی بر `location.hash` و نمایش/مخفی‌سازی `<section>` ها (نه یک SPA router واقعی).
- **مدیریت وضعیت**: متغیرهای سراسری در closure اسکریپت‌ها (`detailState`, `categoryState`, `activeIntroTopic`, ...) — بدون state management واقعی.
- **مدل داده**: کاملاً **hardcode شده به‌صورت آرایه/آبجکت جاوااسکریپت داخل فایل** (`membershipCards`, `categoryCatalog`, `serviceOfferLimits`, `introStories`, `storyItems`). هیچ فراخوانی API/`fetch` واقعی در کل فایل وجود ندارد.
- **پرسیستنس**: فقط `localStorage` — برای:
  - `biawin:onboarding:guest` → وضعیت دیدن تور آموزشی
  - `biawinUnifiedUsers` → آبجکت JSON از کاربران ثبت‌شده به‌صورت `{ [phone]: {name, subscription, email} }`
  - `biawinAuth`, `biawinUserPhone`, `biawinUserName` → وضعیت لاگین ساده
- **رندر داینامیک به روش DOM scraping**: تابع `findServiceImage` تصویر محصولات را با جست‌وجوی DOM موجود (نه از یک منبع داده مستقل) پیدا می‌کند — یعنی تصویر و متن به‌شدت به مارک‌آپ صفحه‌ی «services» گره خورده‌اند.
- **حجم فایل**: بخش عمده‌ی ۲۶ مگابایت به SVG/PNG‌های base64 inline (کارت‌ها، آیکون‌ها، تصاویر کارت‌های مشاور و اسکرین‌شات‌های آموزشی که تک‌تک بالای ۵۰۰ کیلوبایت هستند) برمی‌گردد — این یک نشانه‌ی مهم برای معماری فرانت‌اند واقعی است: تصاویر باید به فایل‌های جدا و CDN/اپتیمایز‌شده منتقل شوند.

## ۵. مدل داده‌ی ضمنی (Entity ها) — پایه برای طراحی دیتابیس در گام‌های بعد

از دل دیتای هاردکدشده، این موجودیت‌ها قابل استخراج‌اند:

- **User**: phone (شناسه اصلی)، fullName، email (اختیاری)، nationalId، birthDate، referral/inviteCode، subscriptionCode
- **MembershipCard (نوع کارت)**: 3 نوع اصلی (Earn/Biawin/Reward) + 8 «کارت اشتراک» (Start/Plus/Family/Prime/Gift/Travel/Lifestyle/Organizational) — هرکدام: title, tier, credit limit, duration, price, benefits[], accessible services[], terms[]
- **UserCard**: نگاشت کاربر↔کارت با وضعیت (فعال/در انتظار/ویژه) و تاریخ انقضا
- **ServiceCategory**: ۱۸+ دسته (نام، توضیح، تصویر، keywords برای جست‌وجو)
- **Product/Offer**: هر آیتم داخل یک دسته — title, group (زیردسته), paymentType (اقساطی/اعتباری/تخفیفی/اقتصادی/اشتراک/...), subtitle, price/priceRange, icon/image
- **PaymentPlan**: ۴ نوع کلی به‌ازای هر محصول (اعتباری، اقساطی ۳-۳۶ ماه، پرداخت کامل، رایگان/جایزه)
- **Order/Purchase**: کاربر، محصول، پلن انتخابی، وضعیت (تکمیل‌شده/در حال پرداخت/تحویل‌شده)، شماره سفارش
- **Wallet**: موجودی جایزه، موجودی کیف‌پول اصلی، تراکنش‌ها (increase/topup، spend)
- **RewardProduct**: ۱۶ کالای جایزه با هزینه دریافت (قابل کسر از کیف‌پول + مابه‌التفاوت از درگاه)
- **Mission (گیمیفیکیشن)**: عنوان، امتیاز، درصد پیشرفت، وضعیت
- **Address**: کاربر، آدرس، گیرنده، شماره تماس
- **Advisor (پرسونای AI)**: نام، نقش، سبک مشاوره، توانمندی‌ها، quote — این‌ها باید در نهایت به یک **AI/LLM service واقعی** با system prompt مجزا برای هر پرسونا وصل شوند
- **ChatMessage**: کاربر، مشاور، متن/صوت، timestamp (برای تاریخچه چت با مشاور)
- **NewsArticle**: ۸ مقاله (عنوان، خلاصه، تصویر، دسته)
- **NotificationSettings**: کاربر، toggle های اعلان (وضعیت خرید، پیشنهادها، ورود دومرحله‌ای)
- **AuthSession/OTP**: شماره موبایل، کد ارسالی، انقضا (باید با یک SMS gateway واقعی جایگزین شود)

## ۶. ویژگی‌ها و منطق کسب‌وکار شناسایی‌شده

1. **Onboarding**: لندینگ با ۴ باکس معرفی → استوری توضیحی → ورود/ثبت‌نام → تور راهنمای ۶ مرحله‌ای فقط برای کاربر تازه‌وارد.
2. **احراز هویت**: OTP پیامکی ۳مرحله‌ای (بدون رمز عبور در فلوی اصلی؛ فقط یک toggle «ورود دومرحله‌ای» در تنظیمات پروفایل به‌عنوان لایه امنیتی اضافه اشاره شده).
3. **کارت‌های عضویت**: کاروسل روی خانه، جزئیات هر کارت، فعال‌سازی (toast تأییدی — بدون منطق واقعی بررسی صلاحیت اعتباری).
4. **کاتالوگ خدمات دو سطحی**: دسته کلی (services) → زیر‌دسته با فیلتر/جست‌وجو (service-category) → جزئیات محصول با ۴ روش خرید (service-detail).
5. **جست‌وجوی سراسری خدمات** (serviceSearch) با نرمال‌سازی حروف عربی/فارسی (ی/ك → ی/ک).
6. **کیف‌پول و پرداخت ترکیبی**: در خرید جایزه، مبلغ ابتدا از کیف‌پول کسر می‌شود و باقی‌مانده باید از «درگاه» (فرم فیک شماره کارت/CVV2/تاریخ انقضا) پرداخت شود.
7. **گیمیفیکیشن**: امتیاز باشگاه، مأموریت‌ها با progress bar، کد دعوت با پاداش دوطرفه.
8. **مشاور هوشمند**: انتخاب پرسونا → چت متنی + صوت (STT/TTS ذکر شده) → quick prompts آماده → قابلیت تعویض کرکتر از داخل چت.
9. **اشتراک‌گذاری بومی**: از `navigator.share` برای اشتراک‌گذاری کارت/خدمت استفاده شده (با fallback به کپی کلیپ‌بورد).
10. **پروفایل کامل**: مدیریت اطلاعات، کارت‌ها، سفارش‌ها، مأموریت‌ها، آدرس، دعوت، اعلان‌ها، پشتیبانی (تیکت/چت آنلاین/FAQ) — همگی UI-only فعلاً.

## ۷. بخش‌هایی که صرفاً UI Mock هستند و به بک‌اند/سرویس واقعی نیاز دارند

| بخش | وضعیت فعلی در پروتوتایپ | نیاز واقعی |
|---|---|---|
| احراز هویت OTP | هر کد ۶ رقمی پذیرفته می‌شود؛ کاربران در `localStorage` مرورگر ذخیره می‌شوند | SMS Gateway واقعی، هش/ذخیره امن، session/JWT، rate-limit |
| اعتبارسنجی و تخصیص اعتبار | مقادیر عددی ثابت و متنی («تا ۳ برابر») | موتور اعتبارسنجی/ریسک، احتمالاً استعلام اعتباری |
| درگاه پرداخت | فرم شماره کارت/CVV2 لوکال، بدون ارتباط با بانک | اتصال به IPG واقعی (شاپرک/زرین‌پال و مشابه) |
| مشاور هوش مصنوعی | پاسخ‌ها و بیوگرافی‌ها استاتیک/از پیش‌نوشته | اتصال به LLM (با system prompt جدا برای هر پرسونا)، STT/TTS واقعی |
| موجودی کیف‌پول/تراکنش | عدد ثابت در HTML | حساب کیف‌پول واقعی با تراکنش‌های قابل‌ردیابی |
| سفارش‌ها/وضعیت پرداخت | چند آیتم نمونه‌ی هاردکد | سیستم سفارش با state machine واقعی |
| اعلان‌ها | فقط toggle UI | سرویس Push/SMS Notification |
| جست‌وجو | فیلتر ساده روی DOM موجود | Search index واقعی (سمت سرور یا client-side روی داده API) |

## ۸. نکات فنی درباره خود فایل پروتوتایپ

- حجم غیرعادی (۲۶MB) عمدتاً به دلیل embed کردن تصاویر SVG/PNG به‌صورت base64 مستقیم داخل attribute هاست (برخی خطوط تنها بیش از ۱ مگابایت طول دارند — مثلاً تصاویر پرسونای مشاوران و اسکرین‌شات‌های آموزشی).
- کل فایل شامل ~۶٬۸۰۰ خط CSS (تماماً در یک `<style>` بزرگ، بدون namespace ماژولار مگر پیشوندهای کلاس مثل `page-home`) و ~۱۵ بلوک `<script>` جداگانه با نام‌های توصیفی (auth, onboarding, story, poster, ...) است که همگی مستقیماً روی DOM سراسری کار می‌کنند.
- هیچ build tool، bundler یا framework در کار نیست؛ یعنی معماری فرانت‌اند واقعی (React/Next.js/Vue/...، تفکیک کامپوننت، تایپ‌اسکریپت، API layer) باید از صفر طراحی شود — پروتوتایپ صرفاً به‌عنوان **مرجع UX/UI** ارزش دارد، نه پایه‌ی کد قابل توسعه.

## جمع‌بندی

پروتوتایپ بیاوین یک **مرجع کامل و بسیار دقیق برای طراحی محصول** است: تمام صفحات، فلوها، کپی‌رایتینگ فارسی، دیتای نمونه و سیستم بصری در آن مشخص شده‌اند. اما از نظر مهندسی، **صد‌درصد یک ماکاپ فرانت‌اندی بدون بک‌اند** است — هیچ API، پایگاه‌داده، احراز هویت واقعی یا سرویس AI در آن وجود ندارد. گام‌های بعدی (استخراج Design System رسمی، معماری نرم‌افزار، Frontend واقعی، Backend، Database) دقیقاً باید همین ساختار UX را با یک معماری قابل‌نگهداری و مقیاس‌پذیر جایگزین کنند.

آماده‌ام برای گام ۲ (استخراج رسمی Design System) هر وقت تأیید بدهید.
